# 程序信任与检测

> 来源：2026-10-23 收件箱「windows怎么分辨外部程序是不是木马」，2026-10-24 提问式学习；2026-11-03 邮件发送 `.bat` 被安全警告拦截

数字签名验证通过，说明什么？能证明程序安全吗？
?
说明发布者身份可信（证书由 CA 核验），且文件自签名后未被改动。
不能证明行为安全：私钥被偷或被滥用时，木马也能带有效签名。
<!--SR:!2026-11-09,7,250-->

「程序调用了敏感 API」能直接判定为木马吗？为什么？
?
不能。敏感 API 有大量正常用途，要结合调用上下文和行为组合判断。
特征码匹配已知样本，误判、漏报都存在，也会被变种绕过。
<!--SR:!2026-11-09,7,250-->

为什么 `.bat` 文件总是提示「此文件没有包含有效的数字签名」？
?
Windows 的 Authenticode 签名放在 PE 头的安全目录指向的证书表里；`.bat` 是纯文本、由 `cmd.exe` 解释，没有 PE 结构，也就没有放签名的位置。
所以 `.bat` 根本无法内嵌签名，这个提示由文件格式决定，不是签名写坏了。
<!--SR:!2026-11-06,3,250-->

邮件下载的 `.bat` 双击会弹「无法验证发布者」，本地新建的同一个脚本却不弹。Windows 靠什么区分？
?
靠文件的 Mark-of-the-Web：浏览器/邮件保存附件时，往 NTFS（一种文件系统）的备用数据流（挂在同一个文件上的命名数据流，不是独立文件） `Zone.Identifier` 写入 `ZoneId=3`（Internet 区域）。
资源管理器按这个流判断来源；本地新建的文件没有该数据流，`Get-Content -Stream Zone.Identifier` 会报「无法打开备用数据流」。
<!--SR:!2026-11-06,3,250-->

网络来源的未签名 `.bat` 弹出「打开文件 - 安全警告」，是禁止执行吗？
?
不是，只是让用户确认的提示；点「运行」就能执行，除非组策略另有硬性拦截。
